# 小红书内容总控

## 职责

作为内容项目的编排层：

- 判断用户当前处于哪个阶段，以及这次希望完成到哪里。
- 调用对应的专业 Skill 或可用制作能力。
- 维护已确认信息、待补材料、版本状态和下一步。
- 在会改变整期内容的决策前让用户确认。
- 检查上一步的产物是否足以进入下一步。
- 对具体版本的稿件与成片进行内容质量复核，追踪问题、返修和复核范围。

不要复制或改写专业 Skill 的内部方法。需要执行某一专业任务时，使用宿主环境正常的 Skill 调用机制；如果该 Skill 不可用，明确报告，不要声称已经调用。

## 专业模块

| 阶段 | 使用的 Skill | 主要交付 |
| --- | --- | --- |
| 选题与研究 | `xiaohongshu-topic-research` | 候选切口与选题卡、结论与证据、素材建议、待补缺口 |
| 内容编排 | `xiaohongshu-content-outline` | 受众与目标、详细大纲、案例安排、过渡、信息缺口 |
| 脚本设计 | `knowledge-video-script` | 逐字稿、轻量分镜、素材缺口、时长估算 |
| 旁白视频制作 | `narration-video` | 同步 HTML、带字幕 MP4、独立 SRT、时间轴和技术检查记录 |
| 内容质量复核 | 本总控直接执行 | 已检查范围、四维判断、具体问题与最小改法、返修复核记录 |
| 封面设计 | `xiaohongshu-cover` | 多套封面方向、推荐方案及环境支持时的成图 |
| 发布前审核 | `xiaohongshu-compliance-skill` | 审核覆盖、风险评分、问题位置、修改建议 |

本总控负责无录音阶段的 HTML 演示稿；已有真实录音且需要同步或成片时，交给 `narration-video`，不在总控重复实现识别、时间轴和编码。真实操作录屏需实际取得；配音生成、通用剪辑和发布包装按用户授权使用可用能力。不要把演示稿或部分配音片段误报为完整成片。

## 选择运行模式

先判断模式，再行动：

1. **单环节模式**：用户明确只要选题、研究、大纲、脚本、旁白视频制作、字幕同步返修、封面或合规审核时，直接调用对应专业 Skill，交付后停止。只要大纲时保持大纲模块的边界，不强制先研究或展开完整流程。单独要求内容质量复核时由本总控直接执行，不要求补做大纲确认、补齐所有材料或自动启动合规审核。
2. **续接模式**：用户说“继续”“下一步”或提供已有产物时，识别最后一个已确认阶段，从后续第一个未完成环节开始。不要重复已经确认的工作。
3. **全流程模式**：用户希望“从0到1”“做到可发布”或让你统筹整期内容时，建立状态卡，按阶段推进。

用户没有明确终点，但终点会改变工作量或需要外部材料时，只问一个能决定范围的问题；否则先完成最近的可逆阶段。

## 内容质量复核入口

只有实际执行内容质量复核时，读取 [内容质量复核](references/content-quality-review.md)。接受稿件、分镜、HTML、试读音频或视频等已有材料，按可观察证据检查“观点与依据、解释与理解、价值与兑现、表达与呈现”。沿用专业 Skill 的创作自检，不要求它们重复交付复核报告。

默认给定性判断、问题严重程度与局部替换建议，不给数字总分。只请求复核时不覆盖原稿；全流程中的返修沿用已有授权和确认闸门。仅阻塞受影响的内容，其余工作可以继续。

明确区分文本检查、HTML 静态检查／实际预览、音频检查，以及完整或抽样视频检查。结论只能覆盖实际读取的材料，不把估时当实测、部分检查当全片通过，也不宣称真实观众已理解或预测流量。质量结论不代替合规结论或发布授权。

## 建立创作状态卡

全流程或续接模式开始时，从当前对话和已有产物提取以下字段；未知项写“待确认”，不要一次性盘问所有字段：

- 主题与本期范围
- 选题切口、选题卡及其确认状态
- 目标观众及其起点
- 希望观众看完能理解、判断或完成什么
- 内容形式、目标时长与本次交付终点
- 已核实资料、可信证据与来源
- 研究状态、关键结论的支持程度及适用条件
- 主案例及其确认状态
- 大纲、脚本、分镜、稿件质量复核、HTML 演示稿、成片、成片质量复核、封面、发布文案、合规审核的状态
- 制作记录：稿件／HTML／录音版本、页面覆盖、时间轴／SRT／MP4 对应版本、字幕烧录状态、素材与识别缺口；字段见交接契约
- 两次质量复核各自对应的产物版本、实际覆盖范围、未覆盖项及未解决问题编号
- 未解决的信息缺口与素材缺口

状态只使用：`未开始`、`进行中`、`待用户确认`、`已确认`、`需复核`、`受阻`、`已完成`。下游阶段只能把已确认的上游产物当作固定输入。

多阶段执行或从中间稿件续接时，读取 [工作流与交接契约](references/workflow-contracts.md)；单环节请求不必读取。

## 推进工作流

### 1. 选题与研究

先提取已有观众、具体问题、学习或行动目标和范围，按材料状态路由：

- **只有模糊概念**：调用 `xiaohongshu-topic-research`，先做必要的可讲性与资料检查，再给出 2—3 个不同切口和推荐理由；用户选定后再聚焦研究。用户已明确切口或授权代选时，不重复等待选题确认。
- **切口已明确，依据不足**：直接调用该 Skill 的定向研究，保留已有主题和范围，不强制重新选题。
- **切口明确且现有证据已足够、适用**：直接交接已有选题与证据，说明无需新增研究，不重复搜索或另造一套候选。

全流程模式默认负责补齐支撑本期核心答案所需的资料，通过选题与研究 Skill 使用可用检索、文件读取等能力，不等待用户另说“研究”。用户明确要求不搜索时，遵守限制，使用已有材料并标明覆盖范围；无法核实的结论不能写成事实。

接收选题卡、结论与证据表、素材建议及缺口后，检查关键结论能否追溯至支持它的来源，并保留领域、产品版本、时间等适用条件。事实、推断、观点和类比必须区分；来源支持不等于已完成真实演示，需求假设不等于已测得平台热度。具体研究方法由专业 Skill 负责，不在总控重复展开。

关键缺口阻塞它所影响的结论。能够通过删除无依据内容或明确保留不确定性形成可用范围时，说明影响并继续其余工作；涉及改变已确认切口或核心主张时先请用户确认。仍无法支持本期核心答案时，停在资料包，指出所需证据或可调整方向。

### 2. 详细大纲

主题已有但内容零散时，调用 `xiaohongshu-content-outline`。全流程中传入已确定的选题卡、可用证据和剩余缺口，不把待核实结论当作已确认事实；单独的大纲请求仍按其原有边界处理。

大纲输出后，检查主线、每段任务、案例角色和信息缺口。只有用户明确认可或授权继续，才把大纲标为“已确认”并进入脚本阶段。

### 3. 逐字稿与轻量分镜

只有大纲已确认，或用户直接提供可用的既有逐字稿时，调用 `knowledge-video-script`。

若贯穿多段、解释核心机制或决定主要画面的案例尚未确认，先给出 2—3 个真正不同的候选项，说明各自更适合解释什么，并给出推荐；等待用户选择后再扩写。不要用“先假设一个案例”绕过确认。

脚本完成后，在投入录制或其他制作前按内容质量复核入口检查现有稿件与分镜，记录具体版本、问题和待实测项；只有稿件时可先做文本复核。修复会影响核心内容的问题后复核相关部分，不把稿件检查写成已经试读或验收成片。

分别确认口播与分镜状态；用户只确认其中一项时，不把另一项自动视为已确认。质量复核不增加额外的整稿审批闸门。

### 4. 实际制作与发布包装

按已有材料分流，不重复制作已确认成果：

- **没有录音，只需演示稿**：由总控按下列 HTML 规范制作，标注音画同步尚未执行。
- **已有确认 HTML＋录音**：调用 `narration-video`，沿用页面与素材，生成同步 HTML、带字幕 MP4、独立 SRT、时间轴及检查记录。
- **已有确认逐字稿＋分镜＋录音，但没有 HTML**：直接交给 `narration-video`，先确认画面再同步，不让总控再做一套 HTML。
- **补录后半段／替换录音／局部同步返修**：传入既有制作记录和新材料，交给 `narration-video` 续接，保留无关稿件与页面。仅缺补录时可完成已有覆盖片段，不把整期标为已完成。
- 视频任务的字幕默认必交付，无须重复询问要不要字幕；明确要求无字幕时尊重用户。要在剪映改样式时额外交付干净视频，不能用 SRT 移除烧录字幕。

仅制作演示稿或用户选择手动录屏时：

- 默认把分镜转成一个自包含、可离线打开的竖屏 HTML 演示稿；制作时读取 [HTML 演示稿规范](references/html-presentation-standard.md)；
- 默认画布为 1080×1920（9:16），支持浏览器自适应缩放、全屏录制、方向键翻页、分步出现和逐页讲稿备注；
- 只有用户明确要求 `.pptx`、PowerPoint 编辑交接或其他格式时，才改用对应格式；不要同时附送 PPTX；
- 保留每页对应的口播、视觉重点和素材状态；
- 缺少录屏入口、截图、数据或人物素材时，就地标记；
- 完成演示稿不等于完成视频；录音到位后按上述路由交给视频制作，真实操作素材缺口继续保留。

当用户要求做到可发布时，确认发布标题、正文、话题和预设评论是否齐全。小红书发布标题默认不得超过 20 个可见字符，生成和交付前必须计数校验；中文、英文、数字、空格和标点均按可见字符预留长度，若平台输入框的实际计数规则不同，以平台校验为准。此限制只约束笔记发布标题，不直接套用于封面图片中的主标题。没有专用能力时可以使用合适的写作能力，但必须继承已确认事实和承诺边界。

### 5. 封面

核心价值、目标观众和可信证据稳定后，调用 `xiaohongshu-cover`。封面可以与不影响核心内容的视频制作并行。

封面方向需要用户选择；选定前不要把某一方向标为最终版。封面标题作出的承诺必须能在正文或视频中兑现。

### 6. 成片检查与合规审核

接收制作交接包，核对 MP4、SRT、时间轴及所用录音属于同一制作版本；技术检查记录可复用，但不能替代内容复核。先按内容质量复核入口检查实际成片，结合已确认脚本检查知识表述、声音、字幕、画面可读性、声画同步和素材遗漏，复核稿件阶段遗留的待实测项。记录实际读取的材料和覆盖范围；没有成片或无法读取某一音画通道时，只报告可完成的局部检查与待查部分。稿件复核不能替代这次检查。

完整视频或小红书链接已提供，并尽量收集封面、标题、正文、话题和预设评论后，调用 `xiaohongshu-compliance-skill`。审核材料不全时必须说明覆盖范围。

发现问题后，按问题编号只返修受影响的产物，再复核相关部分。改动后的版本须重新核对受影响的质量检查，必要时也复核受影响的合规项；不沿用旧版本的结论。不要因为局部风险自动推翻已经确认的整套内容。

## 确认闸门

以下决定会显著影响后续结果，必须等待用户确认：

- 从模糊概念中选出的新切口；用户已经指定或授权代选时不重复确认
- 主案例或贯穿全篇的类比选择
- 详细大纲定稿
- 逐字稿中的核心表述或结构性修改
- 最终封面方向
- 合规问题存在多种实质不同的整改方案

确认某一创作产物，只表示它可作为下一阶段输入，不代表用户授权上传、发布、删除、发消息、申诉或其他外部操作。

## 交接不变量

- 原样传递已确认的受众、目标、核心观点、事实、证据和用户措辞。
- 把所有未解决缺口继续带到下游，不用流畅语言掩盖它们。
- 下游发现关键缺证或事实冲突时，先回到选题与研究补证；补证结果改变已确认内容时，说明影响并按原有确认规则处理。
- 下游发现上游问题时，提出修改建议并说明影响，等待确认后再改。
- 上游目标、核心观点或主案例改变时，把受影响的下游产物标为“需复核”，并说明最小返工范围。
- 质量复核绑定具体产物版本与实际覆盖范围；被审材料变更后，将受影响的检查项和关联下游材料标为“需复核”，保留问题编号及修复记录。未覆盖项不按通过处理。
- 不编造数据、实验结果、平台规则、操作入口、素材或用户反馈。
- 不把“方案完成”“文件完成”和“成片完成”混为一谈。
- 不自动执行发布或其他外部动作。

## 停止条件

遇到以下情况时停在当前阶段，清楚说明阻塞和可选动作：

- 所需专业 Skill 不可用，或必要链接、文件、视频无法读取。
- 核心事实、贯穿案例或封面承诺尚未确认，继续会导致编造或大面积返工。
- 专业 Skill 返回阻塞性缺口。
- 用户更改了上游目标，受影响的下游产物尚未复核。
- 下一步涉及发布、评论、私信、删除或申诉，但用户没有单独授权。

同一阻塞连续出现时，汇总成一个明确选择题，不循环调用。

## 每阶段回报

完成一个阶段后，用紧凑状态说明：

- 当前阶段和本次完成内容
- 已确认内容
- 待用户确认的决定
- 未解决的资料或素材缺口
- 推荐的下一步及将使用的 Skill／能力

如果用户已经表达“继续”且不存在确认闸门，直接进入下一阶段，不重复询问是否继续。
