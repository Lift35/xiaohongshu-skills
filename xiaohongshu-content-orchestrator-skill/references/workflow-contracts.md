# 工作流与交接契约

仅在全流程执行或从中间产物续接时读取。它用于判断阶段是否可进入、需要向下游传递什么，不替代各专业 Skill 的具体方法。

## 阶段入口与完成标准

| 阶段 | 最低入口 | 完成标准 | 下一阶段常见阻塞 |
| --- | --- | --- | --- |
| 选题 | 一个模糊概念、问题或已有明确切口 | 选题卡说明观众、目标、具体问题和范围；切口由用户选定、已指定或授权代选 | 候选切口未选；范围仍不足以形成一期内容 |
| 定向研究 | 已确定切口，或只需补证的现有内容 | 选题卡、结论与证据、素材建议和缺口可交接；拟采用的关键结论有支持或已明确处理其不确定性 | 核心答案仍无依据；来源冲突影响主张；关键资料不可得 |
| 详细大纲 | 已确定主题；零散问题、资料或观点；全流程传入选题卡和可用证据 | 主线、段落任务、案例角色、过渡和缺口清楚，且用户确认 | 主案例未选；大纲仍有结构分歧 |
| 逐字稿 | 已确认大纲 | 口播自然完整，关键条件未丢失，用户确认核心表述 | 事实缺口；时长目标冲突；主案例未确认 |
| 轻量分镜 | 已确认大纲或既有逐字稿 | 每个理解单元有必要画面、重点、时机和素材状态 | 依赖素材未知；声画重复或不同步 |
| 稿件质量复核 | 现有逐字稿；分镜、试读和发布包装按已有材料提供 | 记录版本、实际覆盖、四维判断与问题编号；影响制作的关键问题已处理并复核，待实测项已交接 | 核心解释或依据仍有问题；关键制作承诺无素材支持 |
| HTML 演示稿／制作方案 | 已确认脚本与分镜 | 自包含 HTML 的页面与讲稿逐页对应，交互可用，所有缺失素材已标出 | 录屏入口、截图、人物或数据素材缺失 |
| 成片 | 实际录屏／录音／素材 | 已形成可读取的实际视频文件，版本明确 | 尚未形成成片；文件无法读取 |
| 成片质量复核 | 实际视频文件；既有脚本、分镜及稿件复核记录可用时一并提供 | 记录实际覆盖的音画通道和时段；制作与内容问题已定位；影响进入发布审核的问题已修复并复核 | 关键音画内容未检查；阻塞性问题尚未修复；审核后版本发生相关改动 |
| 封面 | 受众、核心价值和可信证据稳定 | 用户选定方向；标题承诺可被内容兑现 | 证据不足；标题承诺超出内容 |
| 发布包装 | 核心内容稳定 | 标题、正文、话题和预设评论齐全或明确不需要 | 关键信息与成片不一致 |
| 合规审核 | 完整视频或笔记链接；其他发布材料尽量齐全 | 覆盖范围清楚；风险和修改建议已交付；必要整改已复核 | 材料不全；高风险问题未处理 |

明确切口时跳过候选比较；已有证据足够且适用时无需新增研究。只要大纲的单环节请求直接进入大纲，不能将全流程入口要求强加给它。研究中的局部缺口只阻塞相关结论；删除无依据内容或明确保留不确定性后，其他可用部分可以继续。若因此改变已确认的切口或核心主张，先确认变更。

内容质量复核的独立请求直接检查已有材料，不要求补做大纲确认或同时提交稿件与成片。文本、静态 HTML、实际预览、音频及完整／抽样视频的结论分别记录；抽样或通道缺失不构成完整成片验收。上述阶段完成标准针对进入下一阶段，不将局部待查项扩展为整期停工，质量复核也不自动触发合规审核。

| 目标观众 |  |
| 观众目标 |  |
| 形式与时长 |  |
| 本次终点 |  |
| 已核实资料与证据 |  |

| 关键结论与适用条件 | 来源支持程度、时间／领域／产品版本等；未核实部分单列 |

| 逐字稿 | 同上 |

复核记录中的产物版本须能定位到实际被审材料，例如文件名／链接加版本号或文件校验值；尚不能区分版本时注明“版本待明确”，不推定已经审过当前稿。材料改动后，仅将受影响检查项、问题记录及关联产物标为“需复核”；未覆盖内容继续保留待查状态。

## 专业 Skill 交接包

调用下游 Skill 时传递最少但完整的信息：

```markdown
### 本阶段任务
- 要完成的产物：
- 目标时长／形式：

### 已确认且不可擅改
- 目标观众：
- 观众目标：
- 主题与范围：
- 选题切口及确认依据：
- 核心观点：
- 主案例及其角色：
- 可信证据与来源：
- 用户明确保留的措辞或元素：

### 研究交接（涉及研究时）
- 选题卡：
- 结论与证据表：主张、事实／推断／观点／类比、支持来源及定位、核查日期、适用条件、支持程度
- 素材建议：已有／待取得；真实演示已完成／待执行
- 研究覆盖与限制：本次新核实／沿用既有证据；资料不可得或用户限制

### 可由本阶段决定
- 

### 尚未解决
- 资料缺口：
- 素材缺口：
- 待用户决定：

### 上游产物
- 名称或链接：
- 状态：已确认／仅供参考

### 质量复核交接（涉及复核或返修时）
- 被审产物及版本：
- 实际检查方式与覆盖范围：文本／静态检查／实际预览／音频／完整或抽样视频时段
- 结论及未覆盖项：
- 问题编号、位置、严重程度、最小改法及复核方法：
- 已解决／未解决／待补证问题及需复核的下游产物：
```

不要把“仅供参考”的草稿伪装成已确认输入。下游产物若需要改变“不可擅改”字段，先返回变更提议、原因和影响范围。

来源应对应实际支持的结论，优先一手资料，保留关键限定条件。需求假设、少量内容观察和真实平台指标分别标明，不把未访问的平台数据写成“热门”或“观众普遍需要”。用户确认选题表示接受创作方向，不构成对其事实正确性的核实。

## 常见入口路由

| 用户当前提供的内容 | 默认判断 | 下一动作 |
| --- | --- | --- |
| “我想做一期 X”，切口尚不明确 | 全流程起点 | 调用 `xiaohongshu-topic-research`，必要资料初查后给出候选；选定后聚焦研究，再交接大纲 |
| 切口明确，但缺少核心依据 | 定向研究阶段 | 调用 `xiaohongshu-topic-research` 补齐关键资料，保留主题和范围 |
| 主题加零散问题／资料 | 检查范围与依据 | 范围、依据足够时调用 `xiaohongshu-content-outline`；全流程关键缺证时先定向研究 |
| “只整理大纲，不研究” | 单环节大纲 | 直接调用 `xiaohongshu-content-outline`，保留证据缺口，不强制研究 |
| 已有稿件，只需核实事实 | 单环节定向研究 | 调用 `xiaohongshu-topic-research`，定位需补证的主张，不重新选题或重写稿件 |
| 一份未确认大纲 | 大纲确认前 | 检查关键结构与案例选择，等待确认 |
| 一份已确认大纲 | 脚本阶段 | 调用 `knowledge-video-script` |
| 已有逐字稿，只缺画面 | 分镜阶段 | 调用脚本 Skill 的“只补分镜”模式 |
| “帮我复核这份稿／视频的内容质量” | 单环节质量复核 | 本总控读取内容质量复核规范，只检查已有材料，给问题与局部替换建议，不覆盖原稿或自动开展合规审核 |
| 全流程中的脚本／分镜已完成 | 制作前复核 | 本总控做稿件质量复核，处理影响制作的问题，交接真实试读和成片阶段待查项 |
| 已确认脚本和分镜 | 制作阶段 | 默认生成 9:16 单文件 HTML 演示稿；仅在明确要求时改用 PPTX 等格式 |
| 核心内容稳定，只要封面 | 封面阶段 | 调用 `xiaohongshu-cover` |
| 完整视频／笔记链接 | 按请求判断质量复核或合规审核 | 全流程先做实际成片质量复核再进入合规；单项请求只做所要求的检查；目的不明时仅询问影响范围的问题 |
| “继续下一步” | 续接模式 | 从状态卡中第一个未完成且未受阻的阶段继续 |

## 返修路由

质量问题保留编号，先记录位置、实际观察、影响、最小改法与复核方法，再按下列规则分派。只请求复核时交付建议而不覆盖原稿；全流程按已有授权返修，核心观点、案例或结构变更沿用现有确认闸门。复核时记录对应的新版本及问题是否解决，不把局部修复报告为全片重新通过。

- 选题范围未定或关键事实缺证、来源冲突：回到选题与研究；已有明确切口时仅补证。若补证改变已确认主张，提出变更并标记受影响的下游产物需复核。
- 大纲逻辑问题：回到内容结构化创作。
- 口播不自然、解释跳步或声画错位：回到知识视频脚本创作。
- HTML 演示稿看不清、交互异常、素材缺失或录制错误：回到实际制作，不擅自改核心脚本。
- 封面承诺与内容不符：优先修改封面；只有内容本身有误时才回到脚本。
- 合规问题：定位问题来自口播、画面、封面还是发布文案，只修改对应产物；修改后复核受影响部分。

## 全流程完成清单

用户要求“做到可发布”时，至少确认：

- 内容目标与受众明确
- 关键事实有依据，无法确认的内容已删除或标注
- 大纲、逐字稿和分镜已确认
- 稿件质量复核已完成，影响制作的问题已处理，待实测项已交接
- 实际成片完成，最终版本的内容与制作质量检查覆盖明确；阻塞性问题已修复并复核，必要音画内容无待查项
- 封面最终版已选定
- 标题、正文、话题和预设评论已准备或明确不需要
- 合规审核覆盖范围明确，必要问题已整改并复核

完成清单不等于授权发布。
