# HTML 演示稿规范

仅在把已确认逐字稿与分镜制作成演示稿时读取。目标是生成可直接在 Mac 浏览器中全屏录制的演示页面，不是小红书 3:4 图文卡片，也不是网站。

## 默认交付

- 交付一个完整、自包含的 `.html` 文件；CSS 与 JavaScript 写在文件内。
- 默认逻辑画布为 1080×1920（9:16），并按浏览器窗口等比缩放；用户明确要求横屏时再改为 1920×1080。
- 不依赖外链字体、CSS、脚本或在线图片。必要图片使用本地资源或嵌入文件，确保离线打开仍可录制。
- 默认只交付 HTML。仅在用户明确提出 PowerPoint、`.pptx` 或可编辑幻灯片交接时改用对应格式。
- 每页嵌入与该页对应的讲稿备注；演示正文不堆放整段逐字稿。

## 页面编排

1. 以分镜中的“理解单元”决定页数，一页只承担一个主要认知任务。
2. 保留已确认的叙事顺序、核心表述、案例角色与事实边界；发现内容问题时返回上游，不借视觉改写核心观点。
3. 口播负责解释原因、判断和意义；页面负责展示对象、关系、变化、步骤和关键词。
4. 讲到哪个对象，画面同步突出哪个对象。复杂关系优先使用 HTML/CSS 的卡片、流程、对照和高亮，不用整页长文。
5. 同一组页面共用设计 token、网格和组件；允许布局随内容变化，避免连续多页使用完全相同的卡片阵列。
6. 缺少截图、录屏入口、人物或数据素材时，在对应页和备注中明确标记，不伪造界面或结果。

## 交互约定

默认实现以下控制：

- `Space`、`→`、`↓` 或点击右侧：显示下一层内容；本页完成后进入下一页。
- `←`、`↑` 或点击左侧：撤回本页上一层内容；无可撤回内容时返回上一页。
- `F`：进入或退出全屏。
- `N`：显示或隐藏当前页讲稿备注。
- `H`：隐藏或显示录屏控制栏。
- `R`：重置当前页的分步出现状态。
- `Home`、`End`：跳转到第一或最后一页。

为触屏设备补充左右滑动；用 `aria-live` 或等价方式报告当前页，标题与控件需有基本可访问名称。

## 视觉底线

- 使用足以在手机画面中阅读的字号、对比度和安全边距；不要靠缩小文字解决溢出。
- 首屏快速建立问题或价值；结尾页收束核心心智模型或行动，不添加与内容无关的关注口号。
- 动效只用于呈现顺序和注意力引导；默认使用简短淡入或位移，不加入持续漂浮、炫技转场或自动播放。
- 用一个共享脚本控制翻页和逐步出现，不为每页重复 JavaScript 或内联样式，以减少文件体积和生成成本。
- 没有必要的视觉素材时优先使用原生 HTML/CSS 图解，不为“好看”生成装饰图。

## 技术结构

- 使用固定逻辑画布容器，并以 `transform: scale(...)` 或等价方式适配视口。
- 每页使用独立 `<section class="slide">`；未激活页面不参与视觉呈现。
- 需要逐步出现的元素使用统一 `.reveal` 类与可排序状态。
- 每页讲稿存放在页面内的 `<template class="speaker-notes">` 或等价隐藏结构中。
- 控制栏默认在移动鼠标时出现，可由 `H` 完全隐藏，避免录屏入镜。
- 不自动打开新窗口、不主动进入全屏、不请求摄像头或麦克风。

## 交付前检查

至少完成以下静态验证：

1. 页面数量与分镜一致，每页都有唯一标题或可访问名称。
2. 每页都有讲稿备注，备注与逐字稿对应。
3. 内联 JavaScript 通过语法检查；翻页、回退、重置、全屏、备注和隐藏控制均有对应处理。
4. 不存在外链依赖、占位符、`TODO`、示例账号或未替换字段。
5. HTML 中的事实、数字和术语与已确认脚本一致。
6. 文件可直接打开；若环境支持预览，再检查页面溢出、字号、对比度与录屏安全区。

交付时简要说明页数、比例和快捷键，并提供 HTML 文件链接。不要把技术实现过程写进用户交付。
