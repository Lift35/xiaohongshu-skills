# 小红书封面生成 Skill

把用户的笔记或视频内容，转化为可执行、可比较、可验收的小红书封面方案；在环境支持图片生成或设计工具时，继续生成最终封面。

## 核心原则

1. 一张封面最好让目标用户在一秒内得到三个答案：
   - 和我有关吗？
   - 对我有什么用？
   - 为什么值得相信？
2. 信息可以有三个，但视觉中心只能有一个。
3. 主标题负责抓住注意力；副标题负责说明收益；角标负责提供真实可信的证据。
4. 可信证据不是必填项。没有真实证据时，宁可不写，也不要编造“官方”“实测”“第一”“最新”等标签。
5. 先解决信息结构，再考虑装饰和风格。

## 工作流程

### 第一步：读取输入

优先从用户提供的笔记主题、逐字稿、正文、图片或已有封面中提炼：

- 笔记主题
- 笔记内容信息
- 目标人群
- 核心价值
- 可信证据
- 必须保留的文字、人物、产品、品牌元素
- 用户指定的尺寸、风格、颜色或禁用项

信息足够时直接执行，不要为了形式而提问。

信息不足且会明显影响结果时，一次最多提出 4 个简短问题：

1. 这篇内容具体讲什么？
2. 最希望哪类人点击？
3. 用户看完能得到什么最明确的收益？
4. 有哪些真实的可信证据可以放在封面上？

如果用户只提供了正文或逐字稿，先自行推断目标人群、核心价值和可能的可信证据，并清楚标注推断；不要重复询问正文中已经给出的信息。

### 第二步：提炼封面信息

先确定唯一的核心传播句，再分别生成：

- **主标题**：说明主题，同时提供相关性、冲突、结果、问题或好奇心中的至少一种。
- **副标题**：说明用户能获得的具体价值、方法、步骤、结果或适用场景。
- **角标/可信标签**：只使用真实证据，例如官方资料、真实数据、亲自测试、明确身份、案例结果或内容页数。

默认字数规则：

- 主标题优先控制在 8–14 个中文字符，通常不超过 16 个；必要时可分成两行。
- 副标题优先控制在 8–18 个中文字符。
- 角标优先控制在 2–8 个中文字符。
- 同一层级不要同时表达两个核心主题。

如用户已经指定固定文案，不擅自改变信息结构；可以另行给出“原文版”和“精简建议版”。

### 第三步：输出 4 套差异化方案

每次默认输出 4 套方向。四套方案必须在以下至少两个维度上真正不同，而不是只替换几个同义词：

- 点击钩子：反常识、结果收益、步骤教程、权威证据、痛点问题、对比冲突
- 信息结构：主标题优先、副标题优先、数字优先、证据优先
- 版式：居中海报、上下分区、左右分栏、卡片式信息、人物与文字组合
- 视觉气质：极简、知识感、科技感、强冲击、轻松生活化、专业报告感

每套方案包含：

1. 方向名称
2. 适合的目标人群或点击动机
3. 主标题
4. 副标题
5. 角标/可信标签；没有真实证据时写“无”
6. 信息层级
7. 版式说明
8. 画面与视觉元素建议
9. 为什么这套方案可能有效

输出后推荐其中 1 套，并说明推荐理由。不要默认四套都一样好。

### 第四步：生成最终封面

- 用户选定方向后，如当前环境支持图片生成或设计工具，直接生成最终封面。
- 用户明确说“直接生成”“你来决定”或不需要先看方案时，选择最符合内容目标的一套直接生成，不再重复确认。
- 用户只需要文案或方案时，不强制生成图片。
- 当前环境不支持图片生成时，输出可直接交给设计师或图片模型使用的制作说明，包括画布比例、文字、层级、构图、背景、字体气质、素材和禁用项。
- 生成图片后检查中文文案是否完整、准确、无乱码，标题是否仍是唯一视觉中心；发现问题时优先修正文案和层级，而不是继续增加装饰。

### 第五步：验收

逐项检查：

1. 缩小到手机缩略图后，主标题是否仍然清楚？
2. 一秒钟内，能否知道它讲什么、有什么用、为什么可信？
3. 整张封面是否只有一个视觉中心？
4. 主标题、副标题和角标的层级是否清楚？
5. 可信标签是否真实，有没有夸大或伪造权威？
6. 是否存在可以删除而不影响理解的文字、图标、边框或装饰？
7. 文案是否与笔记正文一致，没有“封面承诺大于内容交付”？
8. 中文、数字、英文大小写和专有名词是否准确？

任意一项不通过，先做减法，再重新验收。

## 默认输出格式

按 [references/output-template.md](references/output-template.md) 的格式输出。

需要更详细的标题、信息层级、视觉布局和可信证据规则时，读取 [references/cover-design-sop.md](references/cover-design-sop.md)。

## 迭代与经验回写

用户反馈某个结果不好时：

1. 先修改当前方案。
2. 判断反馈是否能抽象成以后都适用的规则。
3. 将可复用经验写成明确、可执行、可验收的句子，例如：
   - 不写“标题短一点”，改成“主标题默认不超过 16 个中文字符；超过时先压缩再生成”。
   - 不写“画面简单一点”，改成“封面只保留一个视觉中心；删除不影响理解的装饰元素”。
4. 只有在用户明确要求更新 Skill，且当前环境允许编辑 Skill 文件时，才修改本 Skill；否则输出建议新增的规则文本。

## 禁止事项

- 不编造官方背书、数据、测试结果、页数、身份或案例。
- 不把四套方案做成同一文案的轻微改写。
- 不让主标题、副标题、角标和装饰同时抢夺注意力。
- 不为了追求“高级感”牺牲缩略图可读性。
- 不使用与正文无关的夸张承诺诱导点击。
- 不在信息已经足够时反复追问用户。
