# 小红书内容创作 Skills

一套面向小红书知识内容的可复用工作流，从模糊主题开始，逐步完成选题与研究、详细大纲、逐字稿与轻量分镜、可录屏的 HTML 演示稿、封面设计、稿件与成片的内容质量复核和发布前合规审核。

仓库目前包含 7 个 Skill。它们既可以独立使用，也可以由「小红书内容总控」根据当前材料和目标安排调用顺序。

## 推荐工作流

1. **判断起点与目标**：由「小红书内容总控」识别当前阶段、已有材料和本次交付终点。
2. **选题与研究**：用「小红书选题与研究」把模糊概念变成具体切口，先做必要摸底，选定后集中补证；已有明确选题时直接研究，现有资料充分时不重复搜索。
3. **组织内容**：用「内容结构化创作」把主题、问题和资料整理成详细大纲。
4. **形成脚本**：用「知识视频脚本创作」把已确认大纲转成逐字稿与轻量分镜。
5. **稿件质量复核**：由总控在制作前检查观点依据、解释、观看价值和表达，指出具体问题与最小改法；真实语速和音画效果留到后续验证。
6. **实际制作（按需）**：由「小红书内容总控」把已确认脚本与分镜默认生成 9:16 单文件 HTML 演示稿，再配合 Mac 录屏；只有明确要求时才改用 PPTX。取得真实录音后，使用「旁白驱动的知识视频制作」生成音画同步 HTML、带字幕 MP4 和独立 SRT；真实操作录屏需实际提供，发布仍由用户完成。
7. **设计封面**：核心内容稳定后，用「小红书封面」生成不同方向的封面方案与成图；可与实际制作并行。
8. **成片质量复核**：由总控检查实际视频的内容、声音、字幕、画面与同步，按实际读取范围记录结果；修复后检查对应的新版本。
9. **发布前审核**：成片、封面和发布文案齐全后，用「小红书合规官」检查风险；发现问题时，只返修受影响的环节并复核。

## 每个 Skill 是做什么的

### 1. 小红书内容总控

负责整套流程的**判断、编排和交接**。

它会先识别你已经有什么材料、希望做到哪一步，再选择对应的专业 Skill；同时维护受众、目标、核心观点、主案例、证据和待补项，避免不同阶段前后矛盾。

重要决策会设置确认闸门，例如新切口选择、主案例选择、大纲确认、脚本确认、封面方向选择和审核后的整改方案。进入制作阶段后，它会把已确认脚本与分镜默认生成自包含的 9:16 HTML 演示稿，支持全屏录制、逐步出现和逐页讲稿备注；只有明确要求时才改用 PPTX。它不替代其他专业 Skill，也不会擅自补造事实或发布内容。

它还直接负责**内容质量复核**：在脚本形成后、实际成片形成后分别检查“观点与依据、解释与理解、价值与兑现、表达与呈现”。默认交付分项判断、问题位置、修改优先级、最小改法和复查标准，不给数字总分。只有文字时就做文字预审，抽样视频只评价已读范围，不把缺少音画材料当作已完成整片验收。

质量复核可单独使用，无需先补做大纲确认；只要求复核时给诊断及局部替换建议，不覆盖原稿。修订后沿用问题编号核对实际新版本，未覆盖部分和待验证项继续保留。内容质量复核与平台合规审核分别进行。

示例：

> 使用小红书内容总控，从“什么是 Skill”这个模糊主题开始，帮我做到发布前审核。

> 使用小红书内容总控，复核这份稿件的内容质量，告诉我最需要改哪里；只给建议，不改原文。

### 2. 小红书选题与研究

负责把**模糊概念转成具体观众问题，并补齐支撑本期答案的证据**。

只有概念时，先做少量资料摸底，再比较 2—3 个不同切口，并说明每个问题如何从目标观众、使用情境和具体困惑中推导出来，以及依据属于用户反馈、已有观察、创作者判断还是待验证假设；你选定后集中研究。已有明确选题或只需查证现有稿件时，直接沿用范围补证，不重复选题；用户授权代选时可直接推进。

它会主动使用可用的检索与资料读取能力，交付选题卡、结论与证据表、素材建议和缺口，区分事实、观点、推断和类比。无法核实的主张保留为待核实；未执行的演示、未访问的平台数据不会被说成已验证。资料足够即可交给大纲环节，不写详细大纲或逐字稿。

示例：

> 使用小红书选题与研究，我想讲“工具”，但还没有具体切口，先帮我比较几个适合 AI 初学者的方向。

> 选题已经确定，使用小红书选题与研究核实这些结论，整理可用于写作的依据，不要重新选题。

### 3. 内容结构化创作

负责把**已确定的主题和零散材料，组织成适合观众学习的详细大纲**。

它会明确观众起点与学习目标，安排各章节解决的问题、核心要点、例子和过渡，并标出缺少的资料。若主案例会显著影响整期理解或画面设计，会先提供 2—3 个候选案例供用户选择。

它停在大纲，不主动调研事实，也不扩写逐字稿。

示例：

> 使用内容结构化创作，把“什么是 Skill”整理成一份 3 分钟知识视频大纲。

### 4. 知识视频脚本创作

负责把**已确认的大纲转成自然可讲的逐字稿，以及帮助理解的轻量分镜**。

支持三种模式：只写逐字稿、给已有逐字稿补分镜、两者一起制作。它会处理口语化、信息节奏、案例展开和声画配合，并继承上游尚未补齐的素材与证据缺口。

若贯穿多段的主案例尚未确认，它会先提供候选方案，而不会直接替用户决定。它不重新选题、不主动调研，也不制作演示稿或成片。

示例：

> 使用知识视频脚本创作，把这份已确认大纲转成逐字稿和轻量分镜，目标时长 3 分钟。

### 5. 小红书封面

负责把**稳定的内容价值转成具有点击意愿、同时不夸大承诺的封面方案**。

它会读取主题、内容、目标人群、核心价值和可信证据，默认交付 4 套真正不同的文案与视觉方向，并推荐其中一套；在支持图片生成时，交付 4 张独立封面供比较。

它不会编造权威、数据或效果，也不会只做四个换颜色的轻微变体。

示例：

> 使用小红书封面，为这期“什么是 Skill”生成 4 套封面方案和成图。

### 6. 小红书合规官

负责对**实际待发布材料进行发布前风险审核**。

主要输入是完整视频或小红书笔记链接，也可以补充封面、标题、正文、话题和预设评论。它会说明审核覆盖范围，输出总风险分、五项分类得分、问题时间点或位置、证据等级、最小修改建议和发布建议。

它提供风险判断，不代表平台官方审核，不保证一定过审，也不预测限流或流量表现。

示例：

> 使用小红书合规官，审核这个完整视频、封面和发布文案，并告诉我需要修改的位置。

### 7. 旁白驱动的知识视频制作

根据**真实录音决定画面和字幕什么时候出现**，沿用已确认 HTML 或逐字稿与分镜，不重新选题写稿。只有分镜时先确认画面，再进入同步导出。

默认交付烧录字幕 MP4、同步 HTML、独立 UTF-8 SRT、时间轴和检查记录。支持部分录音、换录音重对齐和局部返修；缺配音或真实操作素材时明确标记，不补造案例。预览与视频优先共用画面源，替代重绘必须说明差异。

SRT 不携带样式，也不能移除烧录字幕。需要导入剪映重新设计字幕时，可额外导出无字幕视频。Skill 包含时间轴校验及 SRT 导出程序；语音识别和视频渲染依赖当前环境可用工具，不是自带的渲染引擎。结构校验、7 项程序测试及独立范围判断测试通过，不代表所有环境的端到端渲染均已验证。

示例：

> 使用旁白驱动的知识视频制作，根据我的录音和已确认 HTML，生成带字幕的竖屏视频，同时给我可导入剪映的 SRT。

## 如何选择

| 你现在的情况 | 建议使用 |
| --- | --- |
| 只有一个想法，不清楚下一步做什么 | 小红书内容总控 |
| 只想从模糊概念中找一个具体切口 | 小红书选题与研究 |
| 选题已确定，需要补资料或核实稿件 | 小红书选题与研究的定向研究模式 |
| 主题明确，材料已有但内容零散 | 内容结构化创作 |
| 已有确认的大纲 | 知识视频脚本创作 |
| 已有逐字稿，只缺画面安排 | 知识视频脚本创作的“只补分镜”模式 |
| 已有稿件或成片，需要检查是否讲清楚、呈现顺畅 | 小红书内容总控的内容质量复核 |
| 已确认脚本和分镜，需要可录屏演示稿 | 小红书内容总控（默认生成 HTML） |
| 已有录音和确认演示稿，需要按讲解节奏自动播放并导出带字幕视频 | 旁白驱动的知识视频制作 |
| 核心内容稳定，需要设计封面 | 小红书封面 |
| 视频、封面和文案已经准备好 | 小红书合规官 |
| 希望从任意阶段继续完成整套流程 | 小红书内容总控 |

## 共同边界

- 全流程中关键依据不足时，总控负责路由到选题与研究主动补证；用户明确限制搜索时按限制使用已有材料。
- 缺少事实、数据、案例结果或素材时，会明确标注，不为了完整而编造。
- 内容质量复核记录具体产物版本和实际覆盖；文字估时不等于实测，局部检查不等于全片通过，质量结论不保证流量或替代合规审核。
- 已确认的主题、核心观点和表述不会被下游 Skill 擅自改写；发现结构性问题时会先提出并等待确认。
- 静态 HTML 演示稿仍可由「小红书内容总控」制作；录音驱动的画面同步、字幕和视频导出由独立「旁白驱动的知识视频制作」负责。真实操作录屏需提供，发布不自动执行。
- 这些 Skill 不会代替用户发布、删除内容、发消息或发起申诉，除非另有明确授权并存在相应能力。
